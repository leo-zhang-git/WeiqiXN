# 联机功能准备度

## 当前状态

联机功能尚未开始实现。当前扫描没有发现网络框架、传输层、协议层、房间系统、匹配系统、同步系统或断线恢复系统。

## 已具备的基础

- 本地对局已经有可用的状态流：玩家、当前回合、棋盘状态、落子事件、落子后推进。
- 棋盘状态已经以数据结构保存，而不是只存在于 Unity GameObject 上。
- 落子合法性集中在 `ChessBoardSystem`，具备提取为共享规则服务的基础。
- 事件系统可以作为 UI、本地逻辑和未来网络层之间的内部通信机制。
- 存档系统可为快照、重连缓存或本地复盘提供参考。
- UI 框架和配置系统可以继续扩展房间、匹配、邀请、断线提示等页面。

## 主要缺口

- 没有网络依赖和传输抽象。
- 没有服务端或房主权威模型。
- 没有移动命令协议。
- 没有棋盘状态快照协议。
- 没有玩家身份、座位、准备、房间生命周期。
- 没有断线、重连、超时、投降、终局在网络环境下的定义。
- 没有防作弊边界。

## 推荐联机路线

1. 先定义最小在线对局目标：只做好友房/房间码，还是需要匹配。
2. 选择权威模型：推荐服务端权威或房主权威原型，不推荐两个客户端各自直接认定最终棋盘。
3. 提取规则服务：本地和网络都调用同一个落子校验入口。
4. 定义最小协议：`JoinRoom`、`Ready`、`StartGame`、`SubmitMove`、`MoveAccepted`、`BoardSnapshot`、`PlayerTimeout`、`LeaveRoom`。
5. 明确快照结构：棋盘尺寸、当前玩家、棋子列表或位置字典、回合计时、最后一步、局面版本号。
6. 再接入具体网络 SDK 或自建传输层。

## 阶段验收标准

- 本地对局仍可运行。
- 在线对局能在两个客户端之间同步合法落子。
- 非法落子只在权威端被拒绝，并能回传明确原因。
- 双端棋盘状态有版本号或 hash 校验。
- 断线后至少能安全退出或重新同步快照。
